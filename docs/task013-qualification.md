## Implementation

* Public overload `Estimate_ECC_Euclidean (..., Options := (others => <>); Initial_Transform)`.
* One new export `opencv_video_estimate_ecc_euclidean_seeded` (19 exports total) reusing the
  24-byte `opencv_video_ecc_euclidean_result`; private Ada import with matching scalar types.
* Both Euclidean exports share one internal helper for native invocation, schema, finiteness and
  rigid-matrix validation, `atan2` decoding and atomic publication; Task 011 code is untouched.
* Seed domain: finite, `abs(translation) <= 2**20`, `abs(rotation) <= 1.0` rad, in Ada and C++.

## Distinguishing fixtures and the seed-consumption proof

Native probes on all four versions are tabulated in
`docs/ecc-euclidean-seeded-source-contract.md`. Portable cases asserted by AUnit and the native
boundary test: identity initialization throws for +8, +12 and +12 deg + (2,1) and returns a wrong
finite warp for +10 deg and +10 deg + (2,1) (rho about 0.60); the near seed recovers all of them
(rho above 0.98); the wrong-sign rotation seed throws; a (25,-25) translation seed returns a
different wrong finite result (rho about 0.81). Version-dependent outcomes (-8 deg identity, +15 deg
wrong-rot, +10 deg + (2,1) wrong-rot) are not asserted and appear only in the same-build oracle.
The seed is refined, not returned: with 1 iteration versus 50 the result changes, and all three
components end closer to truth than the seed. A zero seed equals the unseeded call exactly
(`Plain = Seeded = Defaulted`; byte-identical C structs, including failures).

## Independent seeded oracle

`tests/cpp/ecc_euclidean_seeded_oracle.cpp` (links OpenCV only) writes
`obj/oracle/ecc-euclidean-seeded.txt` with 37 fixtures, 30 of them with a genuinely nonzero native
initialization. Ada rebuilds every fixture, checks both checksums and the recorded seed identity,
and compares success/failure, the six reconstructed matrix elements, signed angle (mod 2 pi),
translation and correlation. At least four converged fixtures must differ from the unseeded outcome.
The strict parser was exercised with 17 damaged files through the real test binary (missing, empty,
truncated at the end and mid-record, dropped record, lying end count, missing version, bad magic,
bad format version, stale template and moving checksums, altered seed theta and translation,
altered warp and correlation, flipped outcome, non-numeric field); **all 17 were rejected by
`ECC_Seeded_Direct_Oracle`** (0 unrejected). The oracle is generated by the installed OpenCV, never
from the Ada binding.

## Native boundary, faults, corruption

`run_ecc_euclidean_seeded()` in the actual shim/Core boundary driver covers: shim equals a direct
nonidentity `findTransformECC`; zero seed byte-equal to the unseeded export (including failure
status); two different seeds differ; exact accepted bounds reach native code; 14 invalid seeds
(NaN/Inf angle and translation, just beyond each bound, huge) return `INVALID_ARGUMENT` with the
output bytes unchanged; null template, moving and output; invalid iterations and epsilon; wrong
type and geometry; iteration/epsilon forwarding; constant, noise and wrong-sign-seed
nonconvergence with the sentinel preserved; same-handle and shared-storage inputs; centred
rotation; a non-contiguous Region pair with unchanged parents. With `OPENCV_VIDEO_TEST_FAULTS`
(separate test build): `bad_alloc`, `cv::Exception`, `std::exception` and unknown exception at both
stages (8 cases), eleven post-native corruption modes (NaN/Inf warp and correlation, scaled,
reflected, asymmetric, strict-symmetry-only), all leaving the 24-byte result intact, and the valid
+120/-150 degree **output** warps decoded with `atan2`. A rejected seed never reaches a fault hook.
No production fault hooks exist.

The first attempts at "remove the Ada rotation/translation bound" did not compile (removing the
clause left an invalid expression); they were redone as the bound-widening mutants A2 and A3. The
compile errors are not counted as kills.

**Survivors: M14 and M14.1.** They remove only the C++ `isfinite` terms. They survive because the
check is redundant in the shim: NaN compares false against the bound, flows through `cos`/`sin`
into the matrix, and the later per-element `isfinite` check on the six constructed values still
returns `INVALID_ARGUMENT` before any native call. Observable behaviour is unchanged, so these are
equivalent mutants for the tests and are reported as survivors, not as kills. The Ada
finiteness check (A1) is separately killed. (I did not execute a NaN-seed probe against the M14
build to confirm this reasoning; it follows from reading the code.)

## Memory

A seeded and an identity start run the same native algorithm; only six matrix values differ.
`VmHWM` for the same call on 4.10.0: 1024x1024, identity 103,180 kB vs seeded 103,940 kB;
2048x2048, identity 350,444 kB vs seeded 349,864 kB (some of those probes threw on this texture,
which is expected). No materially different allocation pattern was seen. No maximum-geometry
workload was added to any test; the Task 012 envelope (about 1.3 GB at the 2**24-pixel limit) is
unchanged and is documented, not re-measured.
